# 컴비서 (Combiyso) v1.6.5 — 완전판

내 컴퓨터에서 **파일 정리 · 검색 · 편집 · 명령 실행 · 웹 검색**을 채팅으로 시키는
**로컬 AI 에이전트**입니다.
OpenAI 호환 API 키를 넣어 쓰거나, **로컬 LLM(Ollama)** 에 붙여 인터넷/과금 없이 쓸 수 있습니다.
세션(대화) **개수 제한이 없고**, 모든 대화와 파일 백업은 내 PC에만 저장됩니다.

v1.1.0 에서 추가된 것: **스킬(SKILL.md) · 커스텀 명령(/명령어) · 에이전트 정의(모드) ·
세밀 권한 규칙 · todoread · MCP 권한 종류** — opencode 에이전트의 확장 기능을 이식했습니다.

v1.2.0 에서 추가된 것: **중단 복구(뻗어도 이어서 하기) · 작업 상태 표시줄(단계 · 경과시간 ·
무응답 감지) · 하트비트 · 실행 저널** — 오래 걸리는 작업 중에도 "작업 중인지 멈춘 건지"를
바로 알 수 있고, 프로그램이 갑자기 꺼져도 하던 작업을 이어서 계속할 수 있습니다.

v1.3.0 에서 추가/개선된 것: **속도·자원 최적화 · 저사양 모드(자동) · 시작 속도 개선 ·
세션 목록 캐시 · Ollama 컨텍스트(num_ctx) 정렬** — 같은 작업을 더 적은 메모리로 더 빠르게
처리하고, RAM 8GB 미만 PC에서는 자동으로 자원을 아끼는 설정으로 동작합니다.

v1.4.0 에서 추가된 것: **병렬 하위 에이전트(동시 조사) · git 체크포인트 되돌리기(작업 폴더
통째로 되돌리기) · 이미지/PDF 첨부(비전 모델 · PDF 텍스트 추출)** — 조사는 동시에 돌려 빠르게,
실수는 통째로 되돌리고, 그림과 문서도 채팅으로 넘길 수 있습니다.

v1.5.0 에서 추가된 것: **저사양 자동 최적화(하드웨어 감지 · 런타임 메모리 가드 · 간소 UI) ·
종료 시 메모리/VRAM 회복(모델 자동 언로드) · 다른 PC의 Ollama 붙이기(원격 모델 서버)** —
느린 PC에서도 시스템 에러 없이 돌아가고, 프로그램을 닫으면 자원을 돌려주며,
집 안 다른 PC의 GPU에 올린 모델도 그대로 쓸 수 있습니다.

v1.6.0 에서 추가된 것: **모델 자동 탐색(이 PC · 내부 네트워크) · Ollama 자동 시작 ·
Gemini/OpenAI/OpenRouter 등 API 키 서비스 원클릭 추가** — 버튼 한 번으로 설치된 모델을
찾아 고르고, 같은 공유기의 맥/PC에 있는 Ollama 까지 자동으로 찾아냅니다.
Gemini 는 API 키만 넣으면 바로 사용할 수 있습니다.

v1.6.1 에서 추가된 것: **API 키만 붙여넣으면 끝나는 원클릭 연결(서비스 자동 감지) ·
31개 서비스 · 모델 즉시 전환** — 키 모양(`sk-ant-`, `AIza`, `gsk_`, `xai-` …)으로 서비스를
알아서 찾아 Base URL·모델까지 채우고 바로 연결합니다. 모델은 드롭다운에서 골라
[적용]만 누르면 즉시 바뀝니다.

v1.6.2 에서 추가된 것: **추론(생각) 단계 제어(`ollama_think`)** — qwen3·r1 같은 추론 모델의
생각 단계를 끄면 같은 도구 호출을 하면서 응답이 **약 2배 빨라집니다**. 기본값은 `자동`(모델 기본),
작은 모델·에이전트 작업에는 `끄기`를 권장합니다.

v1.6.3 에서 추가된 것: **설정 보호** — `연결 테스트` API 에 빈 값이 들어와도 저장된 설정이
초기화되지 않습니다(부분 값은 기존 설정에 병합).

v1.6.4 에서 추가된 것: **UI 캐시 문제 해결** — `index.html` 을 `no-store` 로 보내고, 실행 시
`?v=버전` 주소로 열어 브라우저에 남은 예전 화면이 뜨지 않습니다.

v1.6.5 에서 추가된 것: **macOS 실제 앱(.app) · 앱 아이콘 · 바탕화면 바로가기** — 맥에서도
터미널 스크립트가 아니라 **아이콘이 있는 앱**으로 설치되어 응용 프로그램/Launchpad/Dock 에서

## 3. 기능 전체 목록

|---|---|

| `grep` | 정규식 내용 검색 (대소문자 무시, 문맥 줄, 파일명만 모드) |
| `run_command` | 셸 명령 실행 (제한시간·출력 크기 제한) |
| `make_dir` | 폴더 생성 (하위 포함) |
| `copy_file` | 파일/폴더 복사 (덮어쓰기 옵션) |
| `move_file` | 이동 / 이름 변경 |
| `delete_file` | 삭제 (폴더는 재귀 옵션, **삭제 전 자동 백업**) |
| `fetch_url` | 웹 페이지를 읽어 본문 텍스트로 변환 |
| `web_search` | 인터넷 검색 (제목/주소/요약) — API 키 불필요 |
| `todo_write` | 여러 단계 작업의 할 일 목록 기록 (UI에 📋 표시) |
| `todoread` | 기록해 둔 할 일 목록을 다시 읽기 (진행률 포함) |
| `skill` | **스킬의 전체 지침 + 참고 파일**을 불러오기 |
| `task` | **하위 에이전트**에게 조사/작업을 맡기고 결과만 받기 (여러 개를 `tasks` 배열로 **동시 실행** 가능 — 읽기 전용만) |

MCP 서버를 등록하면 그 도구들이 `mcp__<서버>__<도구>` 이름으로 **자동 추가**됩니다.

첨부: 📎 버튼으로 **이미지(비전 모델) · PDF(텍스트 추출) · 텍스트 파일**을 붙일 수 있습니다(3-19).

### 3-2. 스킬 (SKILL.md) — v1.1.0 신규
opencode 와 같은 **점진적 공개(progressive disclosure)** 방식입니다.

* 스킬은 `%APPDATA%\compbiyso\skills\<id>\SKILL.md` 파일입니다.
  ```
  ---
  name: 보고서 만들기
  description: 작업 폴더를 조사해 한국어 Markdown 보고서를 만들 때 사용
  ---

  ## 절차
  1. list_dir(recursive=true) 로 구조 파악
  2. ...
  ```
* 에이전트는 **이름 + 설명만** 시스템 프롬프트에서 보고 있다가, 필요할 때 `skill` 도구로 **본문 전체**를 불러옵니다. (토큰 절약)
* 같은 폴더에 참고 파일을 넣어 두면 `skill` 도구의 `resource` 인자로 읽습니다.
* 쓰는 방법 3가지
  1. 에이전트가 알아서 호출 (설명을 보고 판단)
  2. 입력창에 `/스킬id` 를 쳐서 직접 호출
  3. 설정 → **스킬** 탭에서 **[사용]** 버튼 → 입력창에 자동 입력
* 설정 → 스킬 탭에서 **추가 / 편집 / 중지 / 삭제**. 처음 실행하면 예시 스킬 `example-report` 가 하나 생깁니다(지워도 됩니다).

### 3-3. 커스텀 명령 (/명령어) — v1.1.0 신규
자주 쓰는 지시문을 명령으로 저장해 둡니다. `%APPDATA%\compbiyso\commands\<이름>.md`

```
---
description: 코드 리뷰를 요청합니다
---

다음 파일을 리뷰해줘: $1
추가 지시: $ARGUMENTS
```
* 입력창에 `/` 를 치면 **자동완성 목록**이 뜹니다 (`↑↓` 이동, `Tab` 완성, `Enter` 실행).
* `$ARGUMENTS` = 전체 인자, `$1 $2 …` = 개별 인자.
* 내장 명령 (**모델을 부르지 않고 서버가 즉시 처리**):

  | 명령 | 설명 |
  |---|---|
  | `/help` | 명령·스킬 목록 보기 |
  | `/tools` | 지금 쓸 수 있는 도구 목록 (현재 에이전트 기준) |
  | `/skills` | 스킬 목록 |
  | `/init` | 작업 폴더를 분석해 `COMPIYSO.md` 규칙 초안 생성 |
  | `/compact` | 지금 대화를 요약해 컨텍스트 압축 |
  | `/undo` | 최근에 에이전트가 수정한 파일 되돌리기 |

* 설정 → **명령** 탭에서 사용자 명령 추가/편집/삭제.

### 3-4. 에이전트 정의 (모드) — v1.1.0 신규
에이전트마다 **성격(시스템 프롬프트) + 사용할 도구**를 정합니다.
`%APPDATA%\compbiyso\agents\<id>.md`

| 내장 에이전트 | 종류 | 특징 |
|---|---|---|
| `build` | primary | 기본. 모든 도구로 실제 작업 |
| `plan` | primary | **읽기 전용** — 조사/설계만, 파일 수정·명령 실행 불가 |
| `general` | subagent | `task` 도구가 부리는 범용 하위 에이전트 |
| `explore` | subagent | 탐색 특화 하위 에이전트(읽기 전용, 저온도) |

* 상단 드롭다운에서 **현재 에이전트를 바로 전환**할 수 있습니다. (예: `plan` 으로 바꿔 안전하게 조사만 시키기)
* `task` 도구는 `subagent_type` 으로 하위 에이전트를 고를 수 있습니다 (`explore` 추천).
* 설정 → **에이전트** 탭에서 새 에이전트 생성/편집(도구 체크박스, temperature, 시스템 프롬프트).

### 3-5. 세밀 권한 (Permission) — v1.1.0 신규
opencode 처럼 **종류별 기본 동작 + 규칙**으로 allow/ask/deny 를 정합니다.

**종류별 기본 동작** — 설정 → 권한 탭

| 종류 | 기본값 |
|---|---|
| 읽기/검색 | 허용 |
| 파일 쓰기·수정 | 물어보기 |
| 파일 삭제 | 물어보기 |
| 이동/이름변경 | 물어보기 |
| 복사 · 폴더 생성 | 허용 |
| 명령 실행 | 물어보기 |
| 네트워크 | 허용 |
| MCP 도구 | 물어보기 |

**빠른 설정 버튼**: `🛡 위험한 작업은 물어보기(권장)` / `⚡ 전부 자동 허용` / `🔒 읽기 전용`

**세밀 규칙** (위에서부터 먼저 적용, 위쪽이 우선)
```
도구/종류          패턴              동작
run_command       git push*         물어보기
run_command       rm -rf*           차단
read_file         *.env             차단
write_file        *설계*.md         허용      ← 기본값(물어보기)을 덮어씀
mcp               *                 허용
```
* 경로는 `/` `\` 를 모두 인식하고 대소문자를 구분하지 않습니다.
* **차단(deny)** 은 승인 창도 띄우지 않고 즉시 거부합니다.
* 파일 경로뿐 아니라 명령 문자열, URL, 검색어까지 대상이 됩니다.

### 3-6. 승인 시스템 (안전)

### 3-15. 중단 복구 & 작업 상태 표시 — v1.2.0 신규
오래 걸리는 작업 중에 **"지금 작업 중인지, 멈춘 건지"** 를 바로 알 수 있고,
프로그램이 갑자기 종료(뻗음)돼도 **하던 작업을 이어서** 계속할 수 있습니다.

- **작업 상태 표시줄** (입력창 위): 회전 표시 + 현재 단계(생각 중 / 도구 실행 / 승인 대기 …)
  + **경과 시간** + **무응답 시간** + 여유 메모리.
  - 12초 넘게 응답이 없으면 노란색 "무응답", 45초를 넘으면 빨간색 "응답 없음" 경고로 바뀝니다.
- **하트비트(ping)**: 서버가 4초마다 생존 신호를 보내므로, 모델이 느려도 "살아 있음"이 보입니다.
- **도구 실행 시간**: 도구 카드에 `완료 1.2초` 처럼 걸린 시간이 표시됩니다.
- **세션 목록 표시**: 작업 중인 대화엔 파란 점(진행 중), 중단된 대화엔 노란 점(이어서 가능).
- **실행 저널(체크포인트)**: 매 단계(도구 실행 전/후, 단계 시작)마다 진행 상황을
  `%APPDATA%\compbiyso\runs\<실행id>.json` 에 저장합니다.
  - 프로그램이 갑자기 종료되면 다음 실행 때 자동으로 **"중단됨"** 으로 표시됩니다.
  - 대화를 열면 **"⚠ 이전 작업이 … 상태에서 멈췄습니다"** 안내와 **[▶ 이어서 하기]** 버튼이 뜹니다.
  - 이어서 하면 저장된 진행 내용(도구 결과 포함)을 그대로 불러와 **다음 단계부터** 실행합니다.
  - `[버리기]` 를 누르면 그 저널을 삭제합니다.
- **끊긴 도구 호출 자동 정리**: 저장 시점에 도구 결과가 없으면 안내용 가짜 결과를 채워
  모델 API 오류 없이 재개합니다.

> 참고: 저널은 용량 제한(도구 결과 8,000자, 저널 2MB)이 있어 아주 긴 작업은 최근 단계 위주로 보존됩니다.

### 3-16. 속도 · 자원 최적화 & 저사양 모드 — v1.3.0 (v1.5.0 확장)

**저사양 모드 (설정 → 성능)**
- `자동` (기본): 하드웨어를 감지해 **등급별(lite/low/balanced/full)** 로 자동 조정합니다(v1.5.0).
  RAM 8GB 미만이면 켜지고, 4GB 미만(또는 2코어 이하)은 더 강하게 줄입니다.
- `켜기`: 도구 출력·컨텍스트·단계 수를 줄여 메모리와 CPU를 아낍니다.
- `끄기`: 최대 성능.
- 켜지면 설정값을 강제로 덮어쓰지 않고, **사용자가 기본값에서 바꾸지 않은 항목만** 보수적으로 낮춥니다.
- 실행 중 메모리 압박을 감시해 더 줄이는 **메모리 가드**와 **간소 UI**는 3-20 참고.

**Ollama 컨텍스트 정렬**
- `num_ctx`(컨텍스트 창)를 설정에서 직접 지정합니다(기본 8192).
- 자동 압축 기준을 **num_ctx의 85%** 로 맞춰, 모델이 넘치는 부분을 조용히 잘라내는 문제를 막습니다.
- `keep_alive`(기본 `30m`)로 모델을 메모리에 유지해 매 요청 재로딩 지연을 없앱니다.

**그 밖의 개선**
- **시작 속도**: 실행 파일을 폴더형(onedir)으로 바꿔 시작 시 임시폴더 압축 해제를 없앴습니다.
- **세션 목록 캐시**: 대화가 수백 개여도 목록이 즉시 뜹니다(메타 인덱스).
- **저장 안정성**: 세션 저장을 원자적 쓰기(임시파일 → 교체)로 바꿔 중간 종료에도 파일이 깨지지 않습니다.
- **연결 재사용**: LLM·웹 요청에 HTTP 연결 풀을 써서 단계마다 새 연결을 만들지 않습니다.
- **도구 출력 자르기**: 앞부분과 뒷부분(오류/결과)을 함께 남기는 방식으로 바꿔 정보 손실을 줄였습니다.

### 3-18. git 체크포인트로 통째 되돌리기 — v1.4.0 신규

**여러 파일을 한 번에 되돌리는** 안전망입니다. 기존 파일 백업(1개 단위)과 함께 동작합니다.

- 에이전트가 **파일을 처음 바꾸기 직전**에 작업 폴더 전체 스냅샷을 자동 저장합니다.
- **작업 폴더에 `.git` 을 만들지 않습니다.** 스냅샷은 컴비서 데이터 폴더
  (`%APPDATA%\compbiyso\checkpoints\`)에만 저장되어 사용자의 git 저장소를 건드리지 않습니다.
- 되돌릴 때는 `git checkout` 으로 **내용만** 복원하고, 그 뒤 에이전트가 만든 파일만 지웁니다
  (`git clean` 을 쓰지 않아 사용자가 만든 파일은 지우지 않습니다).
- 되돌리기 **직전 상태도 자동 저장**되므로 되돌리기의 되돌리기가 가능합니다.
- 🗂 백업 버튼 → **⏱ 되돌리기** 탭에서 목록을 보고 `이 지점으로` / `지금 지점 저장` 을 누릅니다.
- `/undo` 명령은 체크포인트가 있으면 체크포인트를, 없으면 기존 파일 백업을 되돌립니다.
- 설정에서 끄거나(`off`), 너무 큰 폴더(기본 20,000개 파일 또는 400MB 초과)는 자동으로 건너뜁니다.
- **git 이 설치돼 있어야** 동작합니다(없으면 파일 백업만 사용).

### 3-20. 저사양 자동 최적화 — v1.5.0 신규

프로그램이 **시작할 때 PC 사양을 감지**해 알맞은 모드로 자동 동작합니다.

- 감지 항목: CPU 코어 수 · 전체/여유 메모리 · GPU/VRAM(NVIDIA) · 운영체제
- 등급: **아주 낮음(lite) · 낮음(low) · 보통(balanced) · 넉넉함(full)**
  - RAM 4GB 미만(또는 2코어 이하 + 8GB 미만) → `lite`
  - RAM 8GB 미만 → `low` / 8~16GB → `balanced` / 16GB 이상 → `full`
- `lite`/`low` 에서는 **도구 출력 크기 · 컨텍스트 · 최대 단계 · 병렬 실행 · 이미지/PDF 크기**를
  자동으로 줄이고, 모델 유지 시간(`keep_alive`)도 **5분/10분**으로 줄여 메모리 부족으로 죽지 않게 합니다.
- **사용자가 기본값에서 직접 바꾼 항목은 자동 조정하지 않습니다.**
- 실행 중에도 **메모리 압박을 2초마다 감시**해(런타임 가드), 부족하면 더 줄이고 채팅에 알려줍니다.
  - 정상 → 주의 → 부족 → 위험 4단계, 상단 `RAM` 배지와 작업 표시줄에 표시
  - 위험 수준에서도 **프로그램이 죽지 않고** 가능한 범위에서 계속 진행합니다.
- 저사양이면 **UI 간소 모드**(애니메이션·그림자·블러 끔)가 자동으로 켜지고, 긴 대화는
  화면에 표시하는 메시지 수를 줄여 브라우저 메모리도 아낍니다.
- `설정 → 성능` 탭에서 감지 결과·실시간 메모리·적용 중인 자동 조정을 한눈에 볼 수 있습니다.
  - `저사양 모드`: 자동 / 켜기 / 끄기
  - `자동 최적화`: 켜기 / 끄기(설정값 그대로)
  - `메모리 가드`: 실행 중 자동 감축
  - `UI 간소 모드`: 자동 / 켜기 / 끄기

### 3-21. 종료 시 메모리 · VRAM 회복 — v1.5.0 신규

프로그램을 닫으면(콘솔 창 닫기 · Ctrl+C 포함) **자원을 시스템에 돌려줍니다**.

- **Ollama 모델 언로드**(`keep_alive: 0`) → 모델이 차지하던 **RAM 과 GPU VRAM** 을 회수
  - `자동`(기본): 현재 사용 중인 서버의 모델만 내림
  - `켜기`: 저장된 다른 PC(원격) 서버의 모델까지 내림
  - `끄기`: 모델을 유지(다음 실행이 빠름)
- 파이썬 캐시(세션 인덱스 · HTTP 연결 풀) 정리 + `gc`
- 프로세스 **작업 세트(working set)** 를 비워 OS 에 메모리 반납
- 실행 중에도 `설정 → 성능 → 🧹 지금 자원 회복` 으로 즉시 회수할 수 있습니다.
  `🦙 모델 내리기` 는 모델만 내립니다.

> 다음 실행 때 모델을 다시 올리므로 **첫 응답이 조금 느려질 수 있습니다**.
> 항상 빠른 첫 응답이 중요하면 `모델 언로드 = 끄기` 로 두세요.

### 3-22. 다른 PC의 Ollama 붙이기 — v1.5.0 신규

집/사무실의 **다른 PC 에 설치된 Ollama 모델**을 네트워크로 붙여 쓸 수 있습니다.

1. **모델을 가진 PC(서버)** 에서 Ollama 를 외부 접속 허용으로 실행합니다.
   ```powershell
   # Windows (PowerShell) — Ollama 종료 후
   $env:OLLAMA_HOST="0.0.0.0:11434"
   ollama serve
   ```
   - 방화벽에서 **11434/TCP 인바운드**를 허용하세요.
   - 같은 공유기(같은 서브넷)에 있어야 합니다.
2. **컴비서를 쓰는 PC** → `설정 → 모델` → **모델 서버** 에서
   이름(예: 거실 PC)과 주소(`192.168.0.10:11434`)를 추가 → **[확인]** → **[사용]** → **[저장]**.
3. 주소는 `http://` 나 포트를 생략해도 자동 보정됩니다(`192.168.0.10` → `http://192.168.0.10:11434`).
4. **[확인]** 은 연결 지연(ms) · Ollama 버전 · 설치된 모델 목록을 보여줍니다.
5. 여러 대를 저장해 두고 **[사용]** 으로 언제든 전환할 수 있습니다(모델·서버 설정은 저장 후 적용).
6. `이 PC` 버튼으로 로컬(`127.0.0.1:11434`)로 즉시 되돌릴 수 있습니다.
7. `설정 → 모델` 아래 **다른 PC에서 이 PC로 접속할 주소**도 안내합니다(서버로 쓸 때 편리).

> 원격 서버가 꺼져 있으면 연결 실패 이유와 함께 **무엇을 확인해야 하는지** 한국어로 안내합니다.
> 사내 프록시를 통해 Ollama 에 접속해야 하면 `Ollama API 키`(Bearer)를 넣을 수 있습니다.

### 3-23. 모델 자동 탐색 · API 키 서비스 — v1.6.0 신규

**① 🖥 이 PC 검색**

- `설정 → 모델 → 🖥 이 PC 검색` 한 번이면 설치된 모델이 **목록으로** 표시됩니다
  (이름 · 크기 · 파라미터 수). **[사용]** 을 누르면 주소와 모델이 자동으로 채워집니다.
- **서버가 꺼져 있어도** `~/.ollama/models/manifests` 를 읽어 설치된 모델을 보여줍니다.
  "Ollama 서버가 꺼져 있어 설치된 모델 N개만 표시합니다" 안내가 뜨면 서버만 켜면 됩니다.
- `이 PC의 Ollama가 꺼져 있으면 자동으로 켜기`(기본 켜짐) 가 있으면
  `ollama app`(Windows/macOS) 또는 `ollama serve` 를 자동 실행하고, 포트가 열릴 때까지 기다립니다(보통 2~3초).
- 검색 결과는 최대 10초 캐시되어 창을 닫았다 열어도 다시 기다리지 않습니다.
- 모델이 `qwen3`·`r1` 같은 **추론 모델**이면 `추론(생각) 단계`를 **끄기**로 두세요.
  같은 도구 호출을 하면서 응답이 약 2배 빨라집니다(맥미니 qwen3.5:4b 실측 8.6초 → 4.1초).

**② 📡 내부 네트워크 검색**

- 같은 공유기에 붙은 **맥/PC 의 Ollama 를 자동으로 찾습니다.** 주소를 외울 필요 없습니다.
- 이 PC 가 붙은 `/24` 대역(기본 3개, 옆 숫자 칸으로 1~8 조절)의 254개 주소를
  **병렬(128 스레드)** 로 확인하므로 보통 1초 안에 끝납니다. 결과는 45초 캐시.
- 찾은 서버마다 **버전 · 응답시간(ms) · 모델 목록**을 보여주고 바로 **[사용]** 할 수 있습니다.
- 상대 맥/PC 에서는 Ollama 를 외부 접속 허용으로 띄워야 합니다.
  ```bash
  # macOS (Ollama 앱: Settings → "Expose Ollama to the network" 켜기)
  launchctl setenv OLLAMA_HOST 0.0.0.0:11434
  # 확인: *:11434 로 보여야 함
  lsof -nP -iTCP:11434 -sTCP:LISTEN
  ```
  ```powershell
  # Windows
  $env:OLLAMA_HOST="0.0.0.0:11434"; ollama serve
  ```
  방화벽에서 **11434/TCP 인바운드**도 허용하세요.

**③ API 키 서비스 (Gemini · OpenAI · Groq …) — v1.6.1 확장**

**가장 빠른 길: `⚡ 빠른 연결`**
1. `설정 → 모델` 맨 위 **`⚡ 빠른 연결`** 에서 **API 키만 붙여넣기**
2. **[연결]** → 키 모양으로 서비스를 **자동 감지**(`sk-ant-`→Claude, `AIza`→Gemini, `gsk_`→Groq,
   `sk-or-`→OpenRouter, `xai-`→Grok, `csk-`→Cerebras, `nvapi-`→NVIDIA, `up-`→Upstage …)
3. Base URL·모델까지 자동으로 채워지고 **저장 + 연결 확인** 후 바로 대화 가능
4. 아래 **모델 드롭다운**에서 골라 **[적용]** → 즉시 모델 교체(설정 저장 불필요)

> 자동 감지가 틀리면 왼쪽 드롭다운에서 서비스를 직접 고르면 됩니다. `[+ 추가]` 방식(수동)도 그대로 있습니다.

## 5. 안전장치

- 모든 파일 경로는 **워크스페이스 안**으로 제한(설정에서 해제 가능하나 권장하지 않음)

- 수정/삭제 전 **자동 백업** (보관 개수 설정 · 언제든 되돌리기)
- 서버는 `127.0.0.1` (내 PC 전용) 에서만 열림
- 실행 전 **승인 창**으로 한 번 더 확인

## 10. 참고 / 문제 해결

- UI는 **브라우저 탭**에서 돌아가므로 앱 자체 메모리 사용이 적습니다(약 50MB).
  실제 메모리는 로컬 LLM(Ollama)이 사용합니다.
- 여러 탭에서 같은 주소로 접속해도 같은 세션 목록을 봅니다.
- 도구를 잘 못 쓰는 소형 모델이면 설정 → **동작** → `도구 호출 방식` 을 **텍스트 프로토콜**로.
- 스킬이 동작하지 않으면 ① 설정 → 스킬에서 **사용** 상태인지 ② 설명(description)이
  “언제 쓰는지” 명확한지 확인하세요. 필요하면 `/스킬id` 로 직접 호출하세요.
- 설정이 꼬였다면 `%APPDATA%\compbiyso\config.json` 을 지우고 다시 실행하세요.
- MCP 서버가 안 붙으면 `npx`/`node` 설치 여부와 명령·인자를 확인하고 **[🔄 다시 연결]**.
- **이미지가 안 보이면**: 모델이 비전을 지원하는지 확인하세요(`llava`, `qwen2.5vl`,
  `llama3.2-vision`, `gpt-4o` 등). 텍스트 전용 모델은 그림을 무시합니다.
- **PDF 텍스트가 안 나오면**: 스캔 이미지 PDF일 수 있습니다(OCR 필요) → 페이지를 이미지로 첨부.
- **되돌리기 탭이 비어 있으면**: `git` 설치 여부와 `설정 → 되돌리기` 가 켜져 있는지 확인하세요.
  작업 폴더가 너무 크면(기본 2만 개 파일/400MB) 안전을 위해 자동으로 건너뜁니다.
- **병렬 조사가 안 되면**: `설정 → 성능 → 병렬 실행` 이 `off` 이거나 저사양 모드일 수 있습니다.
  파일을 쓰는 작업은 안전을 위해 항상 순차 실행됩니다.
- **다른 PC의 모델이 안 붙으면**: ① 그 PC의 Ollama 를 `OLLAMA_HOST=0.0.0.0` 으로 실행했는지
  ② 11434 포트 방화벽 인바운드 ③ 같은 공유기(서브넷)인지 ④ 주소 오타(예: `192.168.0.10:11434`)
  를 확인하세요. `설정 → 모델 → 확인` 이 실패 이유를 자세히 알려줍니다.
- **프로그램을 닫아도 VRAM 이 안 비면**: `설정 → 성능 → 모델 언로드` 가 `끄기` 인지 확인하세요.
  다른 프로그램이 같은 Ollama 모델을 쓰고 있으면 Ollama 가 모델을 유지할 수 있습니다.
  `🧹 지금 자원 회복` 으로 즉시 내릴 수 있습니다.
- **저사양인데 자동 설정이 마음에 안 들면**: `설정 → 성능` 에서 `자동 최적화` 를 끄거나
  `저사양 모드` 를 끄면 설정값을 그대로 씁니다. 직접 바꾼 값은 자동 조정에서 제외됩니다.
- **설정이 꼬였다면**: `%APPDATA%\compbiyso\config.json` 을 지우고 다시 실행하세요.
  그래도 이상하면 `%APPDATA%\compbiyso\logs\error.log` 를 확인하세요(v1.5.0).
